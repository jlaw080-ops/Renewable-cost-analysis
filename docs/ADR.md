# Architecture Decision Records

## 철학
개략 검토용 MVP 속도 최우선. 외부 의존성과 화면 복잡도를 최소화한다. 계산 정확성은 단일 원본 문서(`calculation-formulas.md`)와 테스트로 보장한다. 이전 연료전지 앱에서 검증된 로직은 다시 만들지 않고 재사용한다.

---

### ADR-001: 새 앱·새 레포로 시작
**결정**: 이전 연료전지 앱을 확장하지 않고 새 레포로 시작한다.
**이유**: 이번 앱은 "건물 소비량 예측"이라는 새 축이 추가되어 범위가 넓다. 기존 앱을 헤집기보다 깨끗하게 시작하는 편이 안전하다.
**트레이드오프**: 연료전지 계산 코드는 복사·이식해야 한다. → 이식 후 `lib/calc/fuelcell.ts`로 격리하고 결과를 테스트로 고정한다.

### ADR-002: 용도라이브러리에 전력 + 도시가스 원단위 저장
**결정**: 용도별 라이브러리에 전력·도시가스 원단위를 모두 저장하고, 전기·가스 기준선을 둘 다 산출한다.
**이유**: 건물에너지 통계(연면적당 Mcal/m²)에서 전기·가스 값을 함께 확보 → 신재생 도입 효과를 전기·가스 대칭으로 비교 가능.
**트레이드오프**: 입력 데이터·계산이 늘지만, 가스(연료전지 열생산) 절감을 기준선 대비로 보여줄 수 있어 가치가 큼. 가스는 일반용 도시가스 단가, 부가세 미적용(절감 계산과 대칭).

### ADR-003: 계약전력은 사용자 직접 입력
**결정**: 기본요금 계산용 계약전력(kW)을 자동 추정하지 않고 사용자가 입력한다.
**이유**: 자동 추정은 가정이 많아 오차가 크다. 엔지니어 사용자는 계약전력을 알고 있다.
**트레이드오프**: 입력 항목이 하나 늘어난다. (수용)

### ADR-004: 운전 시작 시각 09:00 고정
**결정**: 시간대별 요금 배분 시 운전 시작을 09:00으로 고정한다.
**이유**: 업무·상업시설 대다수에 무난하고 입력을 단순화한다.
**트레이드오프**: 24시간 시설(병원·데이터센터)은 경부하 비중이 과소 반영된다. → 추후 "운전 시작 시각" 입력 옵션으로 확장 가능.

### ADR-005: 경제성 평가(NPV·IRR·회수기간) 포함
**결정**: 투자비·유지보수비를 입력받아 NPV/IRR/단순회수기간/B-C까지 산출한다.
**이유**: 앱의 핵심 목적이 "경제성 검토"다. 이전 앱의 검증된 수식을 재사용한다.
**트레이드오프**: 입력·계산이 늘어난다. → 경제성 입력은 별도 탭으로 분리해 소비량 검토만 원하는 흐름을 방해하지 않는다.

### ADR-006: AI 검토 의견(Gemini) 제외
**결정**: AI 코멘트 기능을 넣지 않는다.
**이유**: MVP 단순화, 외부 API 키·비용·지연 제거.
**트레이드오프**: 자동 해설이 없다. → 결과 화면을 명확히 설계해 보완. 추후 추가 가능.

### ADR-007: 검토안 저장은 Supabase  ⚠️ ADR-009로 대체됨
**결정**: 검토안(입력값 세트)을 Supabase에 저장/불러온다.
**이유**: 화면+PDF만으로는 재검토가 불편하다. 이전 앱과 동일 스택이라 학습 비용이 없다.
**트레이드오프**: DB 연동·환경변수 관리 필요. → 결과는 저장하지 않고 입력값만 저장, 불러올 때 재계산하여 단순화.

### ADR-008: 스택은 이전과 동일 (Next.js + TS + Tailwind + Vercel)
**결정**: 기존 개발 흐름(Claude Code → GitHub → Vercel)과 동일 스택을 유지한다.
**이유**: 익숙한 도구로 마찰을 줄인다.
**트레이드오프**: 특별히 없음. 차트는 Recharts로 고정(대시보드 수준에 충분, D3 대비 커스터마이징은 제한되나 불필요).

### ADR-009: 검토안 저장을 GitHub Gist로 변경 (ADR-007 대체)
**결정**: 검토안 온라인 저장을 Supabase 대신 **무료 GitHub Gist**(서버 API 라우트 경유)로 한다. 미설정 시 localStorage 폴백.
**이유**: 무료 온라인 저장만 필요(단일 사용자·인증 불필요·소량 JSON). 사용자가 이미 GitHub 계정을 보유하여 추가 가입·DB 운영이 없다. Supabase는 과한 의존성.
**트레이드오프**: 관계형 쿼리·동시성 제어가 없다(단일 사용자 전제라 무방). 토큰 노출 방지를 위해 클라이언트 직접 접근 대신 서버 라우트(`app/api/scenarios`)가 필수 — 이는 오히려 ARCHITECTURE 원안의 API 라우트 구조로 복귀하는 것. 변경 영향은 저장 계층(`lib/storage/*`, api 라우트)에 한정되고 계산·UI·PDF는 불변.
